# تذكيرات فَكّر الخلفية

## التشغيل

- تحتاج إلى PostgreSQL (`DATABASE_URL`) و`SESSION_SECRET` الحالي. لا تُطبع القيم ولا تُضاف إلى الملفات.
- المفتاح العام VAPID متاح من `/api/push/config`. يُشتق المفتاح الخاص داخل الخادم بمشتق مستقل من `SESSION_SECRET`، ولا يُرسل إلى المتصفح. يجب إبقاء السر ثابتًا؛ تدويره يستلزم إعادة تفعيل الاشتراكات.
- طبّق الجداول الجديدة باستخدام `pnpm --filter @workspace/db run push` قبل تشغيل الخادم. يفعل سكربت ما بعد الدمج ذلك في بيئة التطوير. يلزم تطبيق المخطط كذلك في بيئة التشغيل المقصودة قبل استخدام الميزة هناك.
- يمسح الخادم المواعيد المستحقة كل ١٥ ثانية. الجدولة محفوظة في قاعدة البيانات وتُستأنف عند إعادة التشغيل؛ لا يُرسل موعد انتهت مهلة مهمته.
- **يجب أن تظل عملية الخادم قيد التشغيل**. استضافة تُوقف العملية أثناء الخمول لا تحقق إرسالًا في موعده دون خدمة جدولة خارجية. إغلاق صفحة التطبيق لا يوقف العملية بحد ذاته؛ إيقاف بيئة التشغيل يوقف فحص المواعيد.
- يلزم HTTPS ومتصفح داعم وإذن صريح. قد تمنع النوافذ الخاصة والإطارات الاشتراك حتى عند ظهور إذن الإشعارات كمسموح. على iOS يلزم عادة فتح التطبيق المثبّت على الشاشة الرئيسية.

## الخصوصية والإلغاء

الاشتراك اختياري. تُرسل عناوين المهام غير المكتملة ومعرّفاتها ومواعيدها واشتراك المتصفح فقط؛ لا تُرسل المواد أو الملاحظات أو اسم الطالب. معرّف الجهاز قدرة عشوائية تُحفظ محليًا؛ يُحفظ تجزئتها فقط على الخادم. ليس حسابًا أو مزامنة بين الأجهزة.

تتسلسل تغييرات الجدولة والحفظ المحلي لتأكيد تعديل/حذف/إكمال المهمة على الخادم قبل ادعاء النجاح محليًا. لذلك يلزم الإنترنت لهذه العمليات عند تفعيل الخلفية فقط. تستخدم عمليات الإرسال والإلغاء قفلًا مشتركًا في PostgreSQL لمنع تعارضهما، ويتحقق العامل من صلاحية الإشعار مرة أخرى قبل عرضه. ما ظهر بالفعل في نظام التشغيل قبل الحذف لا يمكن سحبه بأثر رجعي بشكل مضمون.

حذف الاشتراك يمحو مواعيده. تُحذف المواعيد المنتهية بعد يوم، والاشتراكات غير المستخدمة بعد ١٨٠ يومًا إن لم تحمل مواعيد مستقبلية. حذف بيانات المتصفح مباشرة يفقد قدرة الإلغاء؛ الأفضل إلغاء الاشتراك داخل التطبيق أولًا. قد تنتهي صلاحية الاشتراك تلقائيًا لدى مزود المتصفح، وعند رفضه بـ404/410 يحذفه الخادم.

## التحقق

- `pnpm --filter @workspace/api-server run test:push`: اختبارات قاعدة البيانات وHTTP والجدولة، مع ناقل إرسال اختباري معزول عن اشتراكات المستخدمين. تغطي التكرار والتعديلات والحذف والإلغاء والرسائل المتأخرة وإعادة المحاولة وانتهاء الاشتراك والتعارض مع الإرسال.
- `pnpm --filter @workspace/fakker run test:push-worker`: يشغّل كود العامل الحقيقي في سياق اختباري دون صفحات، ويتحقق من العرض بعد التحقق ورفض الرسائل الملغاة وفتح المهام.
- الاختبارات أعلاه **ليست إثباتًا لوصول إشعار عبر مزود المتصفح ونظام التشغيل**. لهذا التحقق استخدم ملف متصفح عاديًا غير خاص: فعّل الخلفية، أنشئ مهمة بموعد تذكير قريب، أغلق صفحات التطبيق مع بقاء المتصفح/الخادم يعملان، وتحقّق من الإشعار. أعد التجربة بعد حذف المهمة وقبل الموعد، وبعد إلغاء الاشتراك. لا يمكن ضمان الإشعار إن أوقف المتصفح أو النظام الخلفية.
